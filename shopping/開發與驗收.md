## 資料與模組介面

- 訂單、品項、款式分別有獨立固定 ID；各層保有父 ID。沒有多款式時 UI 將一個預設款式與品項合併輸入。標籤、類別、使用者、圖片與歷史回購均以 ID 引用。訂單與退款保留版本及操作歷史。金額以幣別最小單位存整數；重量以整數單位保存後整批計費。
- 正式帳務使用儲值批次、付款交易、退款交易、FIFO 分配、費用項目及運費分配，均保留來源 ID。退款與運費各自維持交易與分配；統計以交易層淨支出作基礎。歷史重算應先驗證完整受影響區間，再發布新帳務版本；舊版本保留供追溯。
- 一般採購與回貨各用案件及品項數量關聯。可重複計算的成本由原始消費與已確認交易推導。回貨運費交易有唯一回貨案來源。
- 共用待辦以來源類型與來源 ID 作唯一鍵（台灣訂單到貨、回貨到貨、退款確認、儲值費用確認）。購物提交觸發狀態重算；預計日期只寫入到期日。退款待辦透過購物確認實收金額的指令完成。
- 衣櫃採購物來源品項及款式作固定入庫來源鍵；購物傳遞目標數量、尺寸、照片 ID、類別、使用者及成本。衣櫃回傳接受／衝突與對應衣物 ID，保有自行維護的欄位及歷次庫存事件。未開發的分類只建立目標映射。
- 雲端方案候選為 Firebase Auth 單一擁有者、Firestore、可信伺服器指令、Cloud Storage 私有圖片。伺服器以操作 ID、版本及唯一索引處理高一致性寫入，交易規則拒絕匿名與非擁有者存取；離線用裝置佇列保存草稿及待送指令。同欄位衝突保留基底、伺服器及本機值。正式備份需含資料版本、媒體與引用，還原先驗證再發布。
- OCR 優先驗證 Tesseract.js 瀏覽器 worker，繁中／簡中／英數，以多張原圖逐張辨識，保留區域座標與來源再去重。各平台解析要以真實樣本驗收。可信欄位預填、疑義保留，縮圖有明確來源坐標時再擷取。原圖處理完後才壓縮 WebP；雲端圖片按內容指紋建檔，跨模組共用引用。

## 待集中確認的規則及輸入

- 訂單共用折扣與費用的分攤基準，以及商品折扣造成單品成本低於零時的處理方式。
- 跨多個 FIFO 批次的部分退款，退款人民幣如何回補各來源批次、回補款項在後續 FIFO 的排序，以及純金額退款對品項的分攤優先順序。
- 跨境集運費的付款幣別及付款渠道；非台幣的集運費是否使用支付寶 FIFO。
- 主程式與衣櫃正式規格、衣櫃異動衝突的處理介面、整體備份還原要求，以及 Firebase 專案與五平台、集運商去識別化截圖樣本。測試與正式部署以實際環境驗證。

## 版本紀錄

### 2026-11-16 ｜ 消費明細本機開發預覽

- 開啟同資料夾的 index.html。訂單、圖片與字典保存在目前瀏覽器的 IndexedDB。此階段請用測試資料；尚未接上正式登入、同步或備份還原。
- 已寫入消費明細介面，含多品項、多款式、分離的付款與取貨欄位、使用者分配、標籤、調整項目、單據核對與重複檢查。可上傳同單多張截圖與多張商品照片，保存 WebP。截圖目前用於人工核對，大陸端可保存未付款紀錄。
- 已實作獨立的 FIFO 批次扣款與歷史重算，以及回貨試算和分攤函式。尚未接通支付寶帳本畫面及回貨流程。金額用最小貨幣單位、重量以整克計，分攤尾差按餘數、同餘數按固定 ID 處理。
- 已通過 10 項 Node 測試，涵蓋 §26 A 的資料規則、B 的重複比對和金額核對、C 的 FIFO 與歷史負餘額、E 的十組重量例及費用守恆。這些是程式測試；圖片上傳、表單實際操作及 Windows/iPhone 仍需瀏覽器驗證。Codex 內建瀏覽器拒絕開啟本機 file URL。
- 執行測試：node --test shopping/orders.test.cjs shopping/wallet.test.cjs shopping/freight.test.cjs
- 尚待完成：可在五平台實測的 OCR 與縮圖、正式帳本及退款、採購與回貨操作頁、月曆及代辦、衣櫃與撤銷、回饋與回購、Firebase 交易與同步、權限與備份還原驗收。

### 2026-11-16 ｜ 訂單表單欄位調整

- 移除商家名稱、平台訂單編號與取貨方式的手動欄位；保留收貨地址或取貨地點，新增「巧巧郎（私人集運）」。
- 訂單日期與付款日期預設為開啟新增訂單時的台灣時間，皆可更改。預填付款日期不會變更付款狀態。
- 標籤及使用者選擇與管理放在品項內；新款式不另填使用者。商品類別仍為品項選填欄，供衣櫃等目標系統判斷物品類型。
- 新訂單可無平台編號，既有編號仍可供資料比對使用。新增訂單的疑似重複檢查可使用截圖指紋或平台、日期、品項及實付金額。

### 訂單截圖 OCR 預覽

- 新增訂單後，使用「上傳截圖並辨識訂單」一次選取同單多張圖片。首次需連網下載 Tesseract.js 和語言模型。辨識在瀏覽器執行，原圖先辨識再壓縮保存。
- 核對辨識原文與項目，按「帶入辨識結果」後再確認金額並儲存。當前解析明確標示的平台、日期、實付及部分商品欄位。未讀出的欄位由使用者補充。五平台實圖、縮圖裁切及手機操作待驗證。
- 兩項文字解析測試通過，涵蓋重疊去重、衝突金額、無效日期及無歸屬數量。

### 購物筆記版面

- 訂單標題自動呈現日期、平台、品名及原幣實付。筆記按摘要、內容、圖片排列，費用、付款、收貨與品項補充可展開。
- 主畫面保留截圖辨識入口；可在圖片區核對結果。顯示原幣合計，台幣成本仍依正式帳務及回貨介接結果。
- 14 項既有程式測試通過，手機版畫面及瀏覽器實際操作待確認。

### 國內／國外批次建檔

- 「新增訂單」先選國內或國外，同一批共用下單日期、付款方式及選填平台。試算表可貼上多列，每列建立一筆訂單。資料全部核對後才一次儲存。
- 國內付款方式為現金、信用卡、轉帳，轉帳可輸入銀行。國外付款方式為支付寶、信用卡。國外信用卡每筆可填台幣手續費，獨立於原幣實付。
- 截圖保留為訂單附件，頁面已移除 OCR 入口和執行時載入。支付寶批次可建檔，帳務正式扣款待接通。
- 16 項程式測試通過，含批次分欄、錯誤行號、信用卡費用與銀行欄位。
