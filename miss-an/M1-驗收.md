# MISS AN｜M1 本機驗收

在本資料夾執行 `node preview.mjs`，保持終端機開啟，並在 Windows 瀏覽器開啟 http://127.0.0.1:4173/。本機驗收使用瀏覽器儲存區，初始沒有衣物或收納位置。舊版資料需要另行規劃遷移。

「全部模組」提供衣櫃和購物。購物入口載入現有的購物筆記，操作時保留 MISS AN 主導覽。兩個模組都可加入快捷鍵並調整順序。購物沿用原本的 IndexedDB 結構，同協定、同主機、同連接埠的既有購物資料可直接讀取。若原本使用不同網址或連接埠，原訂單仍在原瀏覽器來源，這次尚未做跨來源遷移。正式 Firebase 模式的購物入口目前顯示本機驗收狀態。

## 操作驗收

衣櫃已開放本機手動建檔。直接選「衣櫃 → 新增衣物」即可開始，收納位置可以留空。依後續需求加入選填的「誰的」，可輸入人名或「共用」，並在衣物清單以歸屬及尺寸篩選。瀏覽器已驗證新增衣物、重新載入仍可讀取，以及切換歸屬篩選。

1. 首頁確認臺灣日期、既有 LOGO 及本機測試狀態。從「全部模組」進入「衣櫃」。
2. 從首頁進入「管理快捷鍵」，勾選衣櫃後儲存。重新整理應仍有衣櫃快捷鍵。取消勾選後只會移除捷徑。
3. 開啟「收納位置」，新增「家中」，再新增「衣櫃」並選擇「家中」作為上層。改名「家中」後，下層路徑應立即更新。
4. 嘗試將上層移至下層，或移除仍有下層的位置，介面應提示並保留資料。移除最後一層後才可移除其上層。
5. 執行 `node --test core.test.mjs preview.test.mjs`。瀏覽器已操作驗證設定快捷鍵、進入衣櫃、新增位置與重新整理後讀回。iPhone 安裝和離線啟動待實機驗收。

## Firebase 基礎

`public/config.js` 預設為本機測試。正式環境需先有獨立 Firebase 專案，啟用 Email/Password Authentication 和 Firestore，建立本人帳號，並由管理端加入 `missAnOwners/{本人 UID}` 文件。套用 `firestore.rules` 後填入 Firebase Web App 公開設定，再以 HTTPS 提供 `public/`。正式驗收應分別測試未登入、已登入但未授權、已授權本人三種情境。目前尚未部署、開通資源或驗證遠端權限。

收納階層以單一帶版本的文件交易寫入，使循環檢查及並行變更保護能原子執行。位置移除會保留 ID 和刪除時間。瀏覽器端只在本人通過伺服器權限檢查後顯示正式資料。快捷鍵分別使用 Windows 與 iPhone 的本機設定。

目前為本機建檔與清單試用。圖鑑、照片與批次整理、完整生平與生命週期、跨裝置同步、離線待送、衝突處理及備份仍待完成。正式 iPhone 驗收需以 HTTPS 網址提供 PWA。開始使用雲端資源前需確認專案、區域及費用。
